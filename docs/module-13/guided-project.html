Guided Project: Scales and Facets

and your first slides

In Module 13 you learned to choose scales and facets, to ask “compared to what?”, and to check that every reader can tell your colors apart. Here you make those choices on your own Fairness and Sports data and publish them, for the first time, as a report and slides: the moves your Challenge Project reports and presentations need.

What you’ll hand in

  1. A report page and a slides page, both published on your site.
  2. Their two links, in Blackboard.
  3. Both are built from one script: you edit the code once, and both pages show it.

Two milestones

Milestone When What Graded?
Draft See Blackboard Tasks 0–5 done with checks passing; report published with your WRITE answers; slides as a first draft No: you get feedback
Final See Blackboard (end of Module 14) Report and slides revised with Module 14’s ideas, plus a revision log Yes: the rubric

Both go to the same Blackboard assignment (see Finish and submit). See Blackboard for the due date and time.

Task 5 · Color for every reader

Goal: Use colors every reader can tell apart, and never color alone.

Practice first: D7 · Color for every reader (and the redundant cue in D9)

Step What you do How it’s checked
A5 · Fairness Map a column with few categories (2 to 4) to color or fill, with scale_fill_viridis_d(end = 0.8) (or scale_color_viridis_d()). Run color_check(a5). Add a second cue: direct labels (geom_text() or geom_label()), panels, or the same column on x or y The script (PASS / TO DO): each category its own color, at least 20 in all three rows, a second cue
B5 · Sports The same with a Sports column (or one you make): b5 The script (PASS / TO DO)
Explain your colors (in the report) Say which column you colored by and why. If your first choice failed the color check, say what you changed: fewer categories, grouping rare ones, or panels. Then look at your simulated plot: can you still tell the categories apart? Your instructor reads it (counts under Choices)

What the numbers mean. color_check() simulates how your colors look to readers with three types of color blindness, then measures how far apart the two closest colors are (a standard color difference, delta E). Bigger is easier to tell apart; 20 is our course’s line for clearly different. The three rows are red-green (deuteranopia), red-green (protanopia) and blue-yellow (approximate). Below 20? Choose a column with fewer categories, group rare ones with care (keep small groups visible and say so), or use panels.

See it, not only the numbers. simulate_plot() redraws your plot in the same simulated colors. Your report shows your plot and the red-green (deuteranopia) version side by side, and the other two views below them.

The red-green simulations come from a validated model; the blue-yellow one is an approximation. Machado, G. M., Oliveira, M. M., & Fernandes, L. A. F. (2009). A physiologically-based model for simulation of color vision deficiency. IEEE Transactions on Visualization and Computer Graphics, 15(6), 1291–1298. https://doi.org/10.1109/TVCG.2009.113

What reads what: the script reads data/fairness.csv and data/sports.csv. The report and the slides read the script’s chunks. Render writes docs/reports/gp13_report.html and docs/presentations/gp13_slides.html. After a push, GitHub Pages publishes docs/.

One script, two outputs

scripts/gp13_scales_facets.R   ← you edit the code here
        │ chunks read by name
        ├──► reports/gp13_report.qmd        → your report page
        └──► presentations/gp13_slides.qmd  → your slides page
ImportantEdit the code in the script. The report and the slides only read it.

Your words (findings, headlines, limits) live in the report and the slides.

Each chunk in the script starts with a label line such as ## ---- a1 ----. The report and the slides call the same chunks by name (with knitr::read_chunk()), so when you change a plot in the script and render, both pages show the new plot. Rendering the report doesn’t render the slides: render both before you push.

WarningCommon mistake

If you type code into a chunk in the report or the slides, it is ignored: on render, that chunk runs the script’s code instead. Your change doesn’t show on the page, and the checks don’t see it. A new code chunk you add does run, but only on that page, so your report, slides and script no longer match. Keep those chunks empty and fix the code in the script.

Words you’ll see

  • Script: a file of R code you run a few lines at a time (Ctrl/Cmd + Enter). Here, scripts/gp13_scales_facets.R holds all the code.
  • Chunk: a block of code. In the script, the lines from one label line to the next; in a .qmd file, a block that starts with ```{r}.
  • Chunk label: a chunk’s name. In the script it’s a line such as ## ---- a1 ----; the report and the slides find the code by that name.
  • Quarto: the program that turns a .qmd file into a web page or slides.
  • .qmd file: a Quarto document: your words plus code chunks. Here, reports/gp13_report.qmd and presentations/gp13_slides.qmd.
  • knitr: the R package that runs a .qmd file’s code chunks and puts their output into the document.
  • Render: the Render button. knitr runs the code chunks, then Quarto builds the page or the slides. (R Markdown called this Knit.) It renders only the file that is open.
  • Report: the web page built from gp13_report.qmd: code, output and your findings.
  • Slides: the deck built from gp13_slides.qmd (revealjs: slides that open in a web browser; the arrow keys move between them).
  • knitr::read_chunk(): the line near the top of the report and the slides that reads the script’s chunks, so a chunk named a1 there runs the script’s a1 code.
  • Output: what code produces: a plot, a table, a PASS or TO DO line. Render’s output is an HTML file in docs/.
  • Commit: saves a snapshot of the files you ticked, with a message, in your project’s history (Git tab).
  • Push: sends your commits to your repository on GitHub (with your token).
  • GitHub Pages: the GitHub service that publishes your repository’s docs/ folder as your website, a minute or two after a push.
  • URL: a web address. Your two pages’ URLs are the links you submit.

Ideas for your columns

Starting points; check them in the column list Section 0 prints for your own file (name, type, how many different values). Each dataset gets the same kind of hint: task 2 (a skewed column, or a share for percent labels), task 3 (panels: a group or a year), task 4 (two groups and a numeric column) and task 5 (a column with 2 to 4 categories, or how to make one). Small groups stay in your plots, with their n.

Fairness

  • Adult: task 2 capital_gain (most are 0: keep values above 0 with filter() and say how many); task 3 race; task 4 hours_per_week (or age) by sex; task 5 sex or income.
  • ACS Income NC: task 2 income; task 3 sex or marital_status; task 4 hours_per_week by sex; task 5 sex.
  • Diabetes Hospital: task 2 a share with percent labels (readmission); task 3 gender (one panel has n = 2: keep it) or race; task 4 num_medications by gender, Female and Male (Unknown/Invalid, n = 2, is too small for a cloud: say so); task 5 age.
  • Credit Card: task 2 limit_bal; task 3 sex or marriage; task 4 age (or limit_bal) by sex; task 5 sex, or marriage (two small groups).

Sports

  • WNBA: task 2 a share of wins with percent labels; task 3 season_type (2 regular season, 3 playoffs: name them with if_else()); task 4 make a number first: each team’s share of wins in a season, at home and away (group_by() team, season and team_home_away, then summarize()), then the clouds by team_home_away; task 5 team_home_away.
  • NFL Draft Combine: task 2 a share picked in round 1; task 3 make a group from Round (empty = not drafted) with if_else(); task 4 forty for drafted and not drafted; task 5 that group.
  • Boston Marathon: task 2 a share finishing under a time you choose, from finish_net_minutes; task 3 gender or age_group (80+ has n = 5: keep it); task 4 finish_net_minutes by gender; task 5 gender. Never use name, bib_number or team.
  • Setka Cup: task 2 a share of home wins; task 3 make a group from HomeWinner with if_else(); task 4 the points in game 1 (P1_G1 + P2_G1) by who won the match (HomeWinner); task 5 sets played, Sets_P1 plus Sets_P2, with factor().
  • Sumo: task 2 a share of winning records; task 3 make a weight band from weight_kg with if_else(); task 4 weight_kg for two rank letters from Rank with str_sub() (M and J: J has only 28 records, so its cloud of means is wide); task 5 the weight band, or Rank’s first letter with fct_lump_n() (say what you combined).
  • MLB pitches: task 2 a share of strikes; task 3 player_name; task 4 release_speed for balls and strikes (result B and S); task 5 result (B, S, X).
  • Powerlifting: task 2 a share of first places, from Place; task 3 two periods from Date with year() and if_else() (early years are small); task 4 TotalKg for those two periods; task 5 a bodyweight band from BodyweightKg with cut() (a few missing: drop_na()). Never use Name.
  • WTA Grand Slam: task 2 winner_rank (a few missing: drop_na()); task 3 a year from tourney_date with str_sub(); task 4 minutes on Hard and Clay courts (surface; matches without minutes are left out); task 5 surface.
  • MMA fight decisions: task 2 a share where all judges agree; task 3 a year from date with year() (21 years: two periods read better); task 4 a judge’s margin, abs(judge1_margin), for 3- and 5-round fights (rounds; the 24 twelve-round fights left out); task 5 result_type. Never use the judge1–judge3 columns.

Grading (percentage ranges in the rubric)

The rubric grades the final. The draft gets feedback only.

Levels (all criteria): Exemplary 90–100% · Proficient 80–89% · Developing 65–79% · Beginning 1–64% · No Response 0%.

Criterion Weight Looks at
Code and checks: script runs; checks pass; report and slides render and are published 35% Your code and output, Checks table, both pages
Choices: labels, scale, fixed or free, the clouds’ groups and column, colors and categories, each with a reason; the revision log 25% Your writing, both datasets
Interpretation: findings, limits, small groups, no causal claims 20% Your writing and slides
Innovation and creativity (slides) 10% Your slides, and “One thing I tried in my slides, and why”
AI disclosure 10% AI use line in your report and slides, AI log typed in Blackboard (or the no-AI statement), and copies of all AI conversations uploaded in Blackboard

Innovation and creativity (slides):

  • Exemplary (90–100%): every minimum element, plus an idea of your own (an angle, a comparison, an order, an annotation) that helps the reader see the finding.
  • Proficient (80–89%): every minimum element, close to the penguins example.
  • Developing (65–79%): the example’s structure with new plots dropped in; default or topic-only titles.
  • Beginning (1–64%): the slides don’t convey a finding.

Decoration doesn’t count. An idea that distorts the data or breaks the color rules earns no credit. More slides aren’t more credit. Artistic skill isn’t graded.
